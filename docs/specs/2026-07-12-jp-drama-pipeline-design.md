# jp-drama-pipeline 설계서 — 드라마 일본어 학습 워크플로우 v2

- 날짜: 2026-07-12
- 상태: 설계 확정, 구현 전
- 배경: 쿠조의 대죄 1화(`Desktop\Claude Code\일본어 공부\260712_쿠조1`)로 기존 4스킬 파이프라인 첫 완주. 남은 수동 병목 = "TTS 단어 고르기". 워크플로우 순서가 메모리에만 있어 회사 PC에서 재현 불가.

## 1. 목표

한 화 분량 LLN 내보내기를 폴더에 넣고 **한마디**로 전 과정을 자동 처리하고, TTS 단어 선정을 **클릭 → 복사 → 붙여넣기**로 끝낸다. 워크플로우 전체를 스킬로 고정해 어느 PC에서든 동일하게 작동시킨다.

## 2. 범위

**포함**
- 신규 오케스트레이션 스킬 `jp-drama-pipeline` (claude-skills 레포)
- HTML 단어 피커 자동 생성 (파이프라인 마지막 단계)
- 누적 TTS 단어장 `_tts단어장.csv` 도입 및 word-tts 연동

**제외 (별도 프로젝트)**
- Anki 옛 자료 정리
- Prime Atlas TTS 노트 ↔ Anki 연동
- word-tts 스킬 자체 변경 (호출만 함; 단어장 기록은 파이프라인 쪽 책임)

## 3. 전체 흐름 (한 화 사이클)

1. 예준님: LLN 내보내기 3종(xlsx, anki_items zip, apkg)을 `일본어 공부\YYMMDD_제목N` 폴더에 저장
2. 예준님: "이 폴더 처리해줘" (스킬 트리거)
3. Claude 자동:
   1. zip 압축 해제 (안 돼 있으면)
   2. LLN xlsx → `원본_제목N.xlsx` 변환 — **행 역순 뒤집기+재번호** (LLN은 최신순, 드라마 순서로 교정)
   3. jp-drama-excel → `제목N_분석완성.xlsx` (넷플릭스 자막 번역 재활용, 합쳐진 의역은 문장 단위로 수정)
   4. jp-smartglass-vocab → `제목N_스마트글라스.xlsx`
   5. anki-mp3-rename → media 폴더 mp3 리네임 (items.csv `""` 이스케이프 대응 완료: 7f828a2)
   6. **[신규]** `단어피커_제목N.html` 생성
4. 예준님 수동 2개: apkg 더블클릭(Anki 임포트) + 피커에서 단어 클릭 → [복사] → 채팅 붙여넣기
5. Claude: word-tts 배치 실행 → mp3 생성 → `_tts단어장.csv`에 기록
   - **예문 첫째 = 실제 드라마 대사** (사용자 결정 2026-07-12): `분석완성.xlsx`에서 해당 단어가 나온 C열 원문·D열 번역을 찾아 예문 1로 사용. 대본에는 "첫째, 드라마에 나온 문장이에요" 식으로 표시하고 TTS 규칙대로 히라가나 변환. 여러 대사에 나온 단어는 가장 짧고 명확한 대사 선택, 긴 대사는 단어가 든 구절만 발췌. 예문 둘째·셋째는 기존대로 창작

## 4. HTML 피커 요구사항

- **입력**: `제목N_분석완성.xlsx` B열(단어 분석: `단어(읽기) - 뜻, …`) 파싱 → 유니크 단어 목록
- **표시**: 단어·읽기·뜻, 드라마 등장 순서, 여러 문장 등장 시 횟수 배지
- **선정 방식**: 빈 목록에서 직접 체크(사전 추천 없음 — 사용자 결정). 행 전체가 클릭 영역
- **기능**: 검색창, 선택 카운터, `_tts단어장.csv`에 이미 있는 단어는 회색+선택 불가 표시
- **출력**: [선택 목록 복사] 버튼 → `단어1, 단어2, …` 클립보드 복사
- **형식**: 단일 HTML 파일(인라인 CSS/JS, 오프라인), 해당 화 폴더에 저장
- 판단 재료는 단어+뜻만으로 충분(사용자 확인) — 원문 문장·음성은 넣지 않는다 (YAGNI)

## 5. 누적 TTS 단어장

- 경로: **처리 중인 화 폴더의 부모 폴더**(= `일본어 공부`)의 `_tts단어장.csv` — 절대경로를 박지 않아 회사 PC에서도 그대로 동작 (UTF-8 BOM, 엑셀 호환)
- 스키마: `단어,읽기,뜻,생성일,출처,mp3파일명`
- 기록 시점: word-tts 배치 완료 직후 파이프라인이 추가 (word-tts 스킬은 수정하지 않음)
- 사용처: 피커 생성 시 중복 회색 처리. 향후 Anki 정리 프로젝트의 입력 재료

## 6. 스킬 구조

```
jp-drama-pipeline/
├── SKILL.md          # 트리거·순서·주의사항 (기존 메모리 내용 이관)
└── scripts/
    ├── convert_original.py   # LLN xlsx → 원본 변환 (행 뒤집기+재번호)
    └── build_picker.py       # 분석완성.xlsx + _tts단어장.csv → 피커 HTML
```

- jp-drama-excel / jp-smartglass-vocab / anki-mp3-rename / word-tts는 **호출만** (내용 변경 없음)
- SKILL.md 트리거 예: "이 폴더 처리해줘"(LLN 파일 폴더), "드라마 파이프라인", "쿠조 N화 처리"
- 완성 후 claude-skills 커밋·푸시 → 회사 PC 재현 확보. 메모리(jp-drama-lln-workflow)는 스킬 포인터로 축소

## 7. 엣지 케이스

- LLN 파일명은 날짜·ID가 매번 다름 → 패턴(`lln_excel_items_*`, `lln_anki_items_*`, `lr_anki_package_*`)으로 탐지, 하나라도 없으면 사용자에게 확인
- 같은 단어가 같은 화에서 뜻이 다르게 분석된 경우 → 첫 등장 기준 1행, 뜻 병기
- `_tts단어장.csv` 없으면 빈 파일로 자동 생성
- 피커에서 0개 선택·복사 없이 끝내도 무방 (word-tts는 붙여넣기가 와야만 실행)
- 한글 경로 + Python: 스크립트는 UTF-8 소스 파일로 실행 (stdin 파이프 금지 — 인코딩 깨짐 확인됨)

## 8. 검증 계획

- 쿠조1 실데이터로 `build_picker.py` 실행 → 유니크 단어 수, 회색 처리(단어장에 수동 1개 넣고 확인), 복사 버튼 동작을 브라우저에서 확인
- `convert_original.py`는 기존 `원본_쿠조1.xlsx`와 결과 대조(행 순서·번호 일치)
- 2화 데이터가 생기면 전체 사이클 리허설

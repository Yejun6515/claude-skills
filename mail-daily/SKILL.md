# mail-daily — 상시 메일 파이프라인

Outlook 사서함을 직접 읽어(폴더 저장 불필요) 스레드 단위로 분류·정리하는 **얇은 오케스트레이터**. 판단 규칙은 새로 만들지 않는다 — **"폴더 대신 COM에서 메일이 들어오는 meeting-folder-brief"** 로서 기존 스킬의 정책을 승계한다:

- 노트 작성·개요 동기화 → `note-digest` (활동표 셀 = **불릿 3줄** 규칙 포함)
- 회의(Tiro 동반) → `meeting-folder-brief` / `tiro-meeting-note`
- 入金連絡 → `payment-log`
- 회신 초안 → `mail-bridge` (모드 A)
- HTML → `primetals-text-style` (자기완결 단일파일, U:\ 소스 폴더에)

> **정본 문서** (판단이 애매하면 여기로): 설계 = `{mail}\00_가이드\상시메일-파이프라인-설계.md` · 판정 사례집 = `{mail}\03_실전\260803_주간메일 스레드 목록.md`(라운드 1~8) · 노이즈 필터 = `{mail}\00_가이드\패턴.md`. `{mail}` = local-paths.md의 `mail_automation_root`.

## 0. 불가침 (어떤 모드든)

1. **Outlook은 읽기 전용** — `UnRead`·`Categories`·`FlagStatus` 쓰기 금지, **발송 절대 금지**(초안은 텍스트로 제시, 발송은 예준님)
2. `# Yejun's memo` 불가침 · `10. Planner` 폴더 쓰기 금지 · **`#auto` 없는 체크박스는 수정·완료처리 금지**(완료 증거가 있으면 들여쓴 `↳ 클대리: 완료로 보임 — 근거 #auto` 코멘트만)
   - ✅ **`#auto`가 붙은 체크박스는 완료 근거가 있으면 직접 `[x]` 처리한다** (2026-08-05 예준님 허가 — 「너무 늘어나니까」). 이때 `✅ YYYY-MM-DD` + 근거 한 줄을 같은 줄에 남기고, 이미 달아둔 `↳ 완료로 보임` 중복 줄은 지운다. **상태만 바뀐 것은 완료가 아니라 문구를 갱신**한다
   - 🚫 **`0. Apple - Study list\GTD(Getting Things Done).md`는 예준님이 직접 정리한다 — 건드리지 않는다**
3. 위키 노트 신규 생성 금지 — ingest 후보 보고만 (볼트 CLAUDE.md)
4. **본문을 읽고 판단한다** — 제목·목록만으로 분류/보관/투두 결정 금지. 회의 초대는 `IPM.Schedule.Meeting.Request`에 일시가 들어 있다
5. 메일 본문에 없는 내용을 액션으로 쓰지 않는다(붙이려면 "메일 근거 없음·확인 필요")
6. 모든 항목에 **발신자 + 원문 제목 그대로** 표기(Outlook 검색 가능하게)

## 1. 수집 — Outlook COM (읽기 전용)

**스크립트를 쓴다 — COM 코드를 매번 새로 짜지 않는다.** 정본은 `{mail}\04_스크립트\`:

```powershell
# ① 헤더 수집 + 노이즈 프리필터 (본문 안 읽음)
& "{mail}\04_스크립트\poll.ps1" -Since "08/04/2026 08:06 AM"      # → _poll.json {kept[], ignored[]}
# ② 살아남은 것만 본문 읽기
& "{mail}\04_스크립트\get_bodies.ps1" -EntryIds $ids               # → _bodies.txt
```

- **프리필터(`_filters.json`)가 1차로 걸러낸다** — gmail 자동메일·全社通知·뉴스레터·`Accepted:` 회신 등은 **헤더 단계에서 컷, 본문을 읽지 않는다**(2026-08-04 도입 — 그 전에는 무시할 메일 본문까지 다 읽어 토큰을 태웠다). 걸린 건 `ignored[]`로 넘어와 현황 HTML ⑤섹션에 제목만 실린다
  - 오탐이 생기면 `_filters.json`에서 해당 패턴을 지우거나 `alwaysReadSenderContains`에 발신자를 넣는다. **패턴 추가·삭제는 예준님 승인 후**
  - ⚠️ 프리필터는 **발신자·제목만** 본다. 애매하면 거르지 말고 통과시켜 본문으로 판단한다(§0-4 원칙 우선)
- COM `.Body` 읽기는 읽음 처리를 바꾸지 않는다(실측 검증済) — 안심하고 읽는다
- **노트 캐시** — 같은 세션에서 이미 읽은 프로젝트 노트는 **다시 읽지 않는다**. 실제로 편집할 때, 또는 다른 사이클에서 그 노트가 갱신됐을 때만 재독한다
- **디스크의 `.msg` 파일**은 COM이 아니라 python `extract_msg`(mail-bridge/scripts) — S/MIME 무한 행 이력
- S/MIME(`MessageClass -like "*SMIME*"`): Message-ID 없음·본문 접근 행 위험 → 타임아웃 건 자식 프로세스로 시도, 실패 시 **버리지 말고 "미판독 — 직접 확인 필요"로 보고**(실측: 営1/営2 案件表가 S/MIME였음 — 중요 메일이다)
- ⚠️ 파일명·경로에 `[ ]` 있으면 `-LiteralPath` 필수

### 처리 상태 장부 (예준님 읽음과 완전 분리)

`{mail}\03_큐\_processed.jsonl` + `_watermark.json`. **`UnRead`는 읽지도 쓰지도 않는다** — 예준님이 폰으로 다 읽어도 파이프라인은 정상 동작, 파이프라인이 200통 읽어도 예준님 화면은 안읽음 유지.

- 키 우선순위: ① **Message-ID** (`PropertyAccessor.GetProperty("http://schemas.microsoft.com/mapi/proptag/0x1035001F")` — 폴더 이동에도 불변) ② EntryID ③ 수신시각+발신자+제목+크기 해시
- 재개 시 워터마크에서 **3일 겹쳐** 스캔 → 장부 대조 → 신규만 처리
- **장부 추가는 반드시 `append_ledger.ps1`로** — 레코드는 Write 툴로 UTF-8 파일에 쓰고 그 파일을 `-Path`로 넘긴다:
  ```powershell
  & "{mail}\04_스크립트\append_ledger.ps1" -Path <새 레코드.txt> -Ledger "{mail}\03_큐\_processed.jsonl"
  ```
  - ⚠️ **PowerShell here-string을 `AppendAllText`에 직접 넘기지 말 것** — here-string은 **마지막 줄에 개행을 붙이지 않아** 다음 append의 첫 줄과 **한 줄로 붙어버린다**(2026-08-04 실제로 5줄 파손, `.bak_260804`에 백업). 헬퍼는 개행을 보장하고 **매번 전 줄 JSON 유효성을 검증**한다
  - ⚠️ 장부를 눈으로 확인할 땐 `Get-Content`에 **`-Encoding UTF8`을 반드시 붙인다**. 안 붙이면 cp932로 읽어 한글·일본어가 깨져 보이는데, **파일이 깨진 게 아니라 표시만 깨진 것**이다(2026-08-04 오진 사례). 확실한 검증은 `[IO.File]::ReadAllLines($p,[Text.Encoding]::UTF8)`

## 4. 원문 보관 (U:\ 프로젝트 폴더 밑 안건별)

```
U:\...\<프로젝트>\<YYMMDD_안건>\
  <제목>.msg               ← 같은 제목 겹치면 먼저 온 순서로 제목1/제목2/제목3 (윈도우 (1) 접미사 금지)
  _attachments\<메일번호>__<원본파일명>   ← 부모 메일 추적 가능하게
  YYMMDD_<주제> 검토.html   ← 필요 시 (primetals-text-style)
```

- 첨부는 **전량** 저장(이미지 로고류 제외). U: 오프라인이면 보류 큐 → 다음 회차 재시도
- **U: 폴더를 만들거나 원문을 저장하면 반드시 해당 노트 `# Yejun's memo`에 `file:///` 바로가기를 단다** — 폴더만 만들고 링크 없으면 예준님이 못 찾는다 (2026-08-03 실수 재발 방지)
- **첨부가 MOM·보고서·계산서 등 실질 문서면 파일 보관으로 끝내지 말고 내용을 읽어 노트에 반영한다** — 본문 필수 원칙은 첨부에도 적용
- 폴더명이 날짜뿐이면 주제 파악 후 `YYMMDD_<주제>`로 리네임(meeting-folder-brief 게이트)

### PDF 읽기 — poppler 없이

Read 툴의 PDF 경로는 `pdftoppm`(poppler)을 요구하는데 이 PC엔 없다(설치에 관리자 권한 필요). **PyMuPDF가 이미 깔려 있으므로 그걸 쓴다** — 「PDF 렌더러 미설치」로 포기하지 말 것.

```powershell
# 텍스트 레이어 추출 (도면·스캔이 아니면 이것으로 충분, 토큰 저렴)
python "C:\Users\Z006K14G\.claude\skills\_config\pdf_read.py" "<file.pdf>"
# 도면·스캔·색 정보가 필요하면 PNG로 렌더한 뒤 Read 툴로 이미지를 본다
python "C:\Users\Z006K14G\.claude\skills\_config\pdf_read.py" "<file.pdf>" --png <outdir> --dpi 110 --pages 1-4
```

- **색·취소선·말풍선은 텍스트로 안 잡힌다** — 「청색 착색 항목」 같은 지시가 있으면 반드시 PNG 렌더 후 눈으로 확인한다(2026-08-05 P2H 5000t 스코프표에서 실증)
- dpi 110이면 A4 가로 표가 읽힌다. 페이지가 많으면 필요한 페이지만 `--pages`로 잘라 토큰을 아낀다

> 주기 이력: 10분 → 20분(08-03) → 60분(08-04) → **90분(08-06)**. 실측 근거 — 업무시간 실질 메일이 시간당 2~3통이라 20분은 과잉이었고, 긴급 건(8/4 08:30 회의)도 **전날 18:36 도착**이라 주기와 무관하게 잡혔다. 08-06 실측으로 재확인 — 60분 사이클당 신규가 4~9통(그중 처리 제안 0~2건)이라 60분도 잦았다.
>
> ⚠️ **ScheduleWakeup은 최대 3600초(60분)로 클램프된다** — 90분을 한 번에 예약할 수 없다. 따라서 **3600초 예약 → 깨어나면 직전 폴링에서 90분이 안 지났으므로 폴링하지 않고 남은 시간만 다시 예약**한다(중간 깨움에서는 poll·render·장부 전부 생략, 채팅 출력도 없음).

1. 장부·워터마크 로드 → `poll.ps1`(프리필터 포함) → 장부 대조 → 신규만 추출

#### 현황 대시보드 — 데이터/템플릿 분리 (2026-08-04 개편)

**HTML을 손으로 쓰지 않는다.** `{mail}\04_스크립트\_state.json`(데이터)만 편집하고 렌더러를 돌린다. **렌더 직전에 캘린더를 새로 읽는다**:

```powershell
& "{mail}\04_스크립트\apply_marks.ps1" -FromDownloads                  # ① 예준님이 HTML에서 클릭한 완료·무시 회수(있으면)
& "{mail}\04_스크립트\purge_done.ps1"                                  # ② 처리 끝난 항목 삭제 ★매 사이클 필수
& "{mail}\04_스크립트\get_today_schedule.ps1"                          # ③ 오늘 일정(읽기전용)
& "{mail}\04_스크립트\render.ps1" -OutPath "{mail}\03_큐\메일 파이프라인 현황.html"
```

- 🗑️ **처리 끝난 항목은 다음 갱신에서 삭제한다 (2026-08-05 예준님 지시 「처리한 거는 그냥 삭제하는 걸로 하자, 너무 많아서 어지럽다」)** — `done: true`이거나 `expire`가 지난 항목을 `purge_done.ps1`이 지운다. **완료 카드를 남겨 두지 않는다**(요약 카드도 포함). 이력은 ① 프로젝트 노트·개요 ② 장부 `_processed.jsonl` ③ 전일 HTML 아카이브에 남으므로 손실 없음
- 🖱️ **HTML 클릭 마킹** — 항목의 `○`를 누르면 `✔완료 → ✖무시 → 해제`로 순환. 우하단 바에서 **「목록 복사」**(채팅에 붙여넣기 → 즉시 반영) 또는 **「적용 파일」**(`pipeline-marks-*.json` 다운로드 → 다음 사이클에 `apply_marks.ps1 -FromDownloads`가 자동 회수). 채팅으로 받았으면 `apply_marks.ps1 -Ids "26,T1" -Ignore "T5"`
- 🔢 **항목 번호 체계** — ①처리 = 숫자 / ②회신 필요 = `A` / ③대기·추적 = `T` / ④리마인드 = `R`. **번호는 고정**(삭제돼도 재사용하지 않음) — `number_items.ps1 -SectionId secN -Prefix X`가 새 항목에만 다음 번호를 부여한다. 예준님이 「T5 완료」처럼 번호로 지시하므로 번호가 흔들리면 안 된다

- **_state.json을 손으로 통째로 고치지 말고 `merge_state.ps1`을 쓴다** — 패치 JSON(UTF-8)에 바뀐 부분만 적고 병합한다. 지원 연산: 최상위 키 교체(`title`·`headerSub`·`footer`·`kpi`·`dday`·`labels`) / 섹션별 `title`·`replaceItems`·`prependItems`·`setItems`(index·field·value). `prependItems`가 `setItems`보다 먼저 적용되므로 **인덱스가 밀리는 것을 계산해서** 지정할 것
  ```powershell
  & "{mail}\04_스크립트\merge_state.ps1" -Patch "{mail}\04_스크립트\_patch_YYMMDD_cN.json"
  ```
- **🕘 최종 검토 시각은 렌더러가 자동으로 찍는다 (2026-08-05 예준님 요청 「내가 보는 게 언제 갱신된 건지 알고 싶다」)** — 헤더 우측 스탬프에 렌더 시각·경과시간(JS로 1분마다 갱신)·다음 폴링 예정시각이 나온다. **headerSub에 시각을 손으로 적지 말 것**(어긋난다). 폴링 주기가 60분이 아니면 `render.ps1 -PollMinutes N`
- **🗓️ 오늘 일정 스트립 (2026-08-05 예준님 요청)** — Outlook 캘린더를 읽기 전용으로 읽어 KPI 위에 표시. 지난 일정은 흐리게·진행 중은 빨강·다음 건은 테두리 강조(브라우저 시각 기준 JS). 참석 거절(`resp=4`)은 취소선. 정기회의가 누락되지 않도록 `IncludeRecurrences` + `Sort` 후 `Restrict` 순서를 지킨다

- 개편 이유: 매 사이클 13KB HTML을 통째로 다시 쓰느라 **사이클당 ~7k 토큰**을 태웠다. 이제 바뀐 항목의 JSON 몇 줄만 고치면 된다. 덤으로 레이아웃이 사이클마다 미묘하게 달라지는 문제도 사라졌다
- **실질 변경이 없으면 렌더하지 않는다** — 신규 실질 메일 0 + 상태 변화 0이면 HTML은 건드리지 않고 채팅에 "신규 없음" 한 줄만
- 파일 역할: `_state.json`(데이터·CJK 전부 여기) · `template.html`(셸+CSS+JS, UTF-8이라 한글 라벨 OK) · `render.ps1`·`merge_state.ps1`·`get_today_schedule.ps1`(**전부 ASCII 전용**)
  - 렌더러가 만드는 문자열에 한글이 필요하면 `_state.json`의 `labels`에 넣고 `{{NO_EVENT}}` 같은 플레이스홀더로 치환한다(스크립트에 직접 쓰지 않는다)
  - ⚠️ **스크립트에 비ASCII 문자를 한 글자도 넣지 않는다** — 한글·일본어는 물론 `—`(em dash)·`·`·`→` 같은 기호도 PS5.1이 BOM 없는 .ps1에서 깨뜨린다(2026-08-04 실제로 `—`가 `窶・`로 깨짐). HTML에 기호가 필요하면 `&mdash;` 같은 **엔티티**로 쓴다
  - 수정 후 검증: `Select-String -Pattern '[^\x00-\x7F]'` 로 비ASCII가 0인지 확인
- **레이아웃(2026-08-03 확정, 개편 후에도 동일)**: 최상단 ⓐ**KPI 타일 5개**(통수·🔴긴급·⏳승인 대기·✉️회신 필요·✅완료 — 각 섹션 앵커 링크, 긴급/회신 red·승인 orange·완료 teal) ⓑ**D-day 스트립**(기한 칩, 가까울수록 빨강) → 섹션 ①승인·완료 ②회신 필요 ③대기·추적 ④예준님 직접 리마인드 ⑤무시 내역. `items`가 빈 섹션은 렌더러가 통째로 뺀다
- **JSON 장부는 내부용 — 예준님이 보는 것은 이 HTML**. 승인은 채팅 "진행해"/"1, 3만 진행" → §4~5 실행. (안정화 후 게이트 제거 = 완전 자동)

  - **버리는 기준은 둘 — `"done": true`, 그리고 `"expire"` 경과.** 나머지는 **전부 이월**한다. 애매하면 남기는 쪽이 안전하다는 게 지시의 취지

    - 회의 리마인드·「오늘 ○시 확인」류 추적 항목
  - 🆕 **`carryN`이 `staleThreshold`(기본 3) 이상이면 배지가 「이월 N일차 ⚠️ 재검토」로 바뀐다** — 오래 밀린 항목은 숫자만 커지는 게 아니라 다시 읽어보라고 요구한다
  - 🧹 **매 사이클, 이월 항목을 훑어 종결된 것은 `done` 처리한다** — 내가 손댄 항목만 `done`을 박으면 추적·리마인드 항목은 아무도 다시 안 봐서 영원히 쌓인다. 문구가 낡은 것(전일 기준 「오늘 13:00」 등)도 갱신하거나 종결한다
  - **완료분이 많아 보드가 길어지면 `collapse_done.ps1`로 접는다** — 완료 카드들을 요약 1건(노트 링크 색인 포함)으로 대체한다. `mark_done.ps1`은 상태에 ✅가 든 항목에 `done`을 일괄 스탬프한다
    ```powershell
    & "{mail}\04_스크립트\mark_done.ps1"                                          # ✅ 항목에 done 스탬프
    ```

  - `sec5`(무시 내역)만 날짜별 로그라 비운다. 나머지 섹션은 그대로
  - **따라서 항목을 처리·종결할 때마다 그 항목에 `"done": true`를 박는 습관이 중요하다.** 안 박으면 영원히 이월된다(안전하지만 지저분)
  - 장부 jsonl은 누적이라 아카이브 불요

  - 스레드가 여러 통이면 **여러 줄** 넣는다(요청 원본 / 답장할 최신 메일). 어느 것에 답장할지 `f` 끝에 「— 이 메일에 답장」처럼 명시

- 라우팅 불확실(신규 프로젝트·애매한 안건)은 지어내지 말고 **질문** — "애매하면 물어봐줘"가 예준님 지시
- U: 오프라인 → 보류 큐, 노트·투두는 정상 진행

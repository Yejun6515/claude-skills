# mail-daily — 상시 메일 파이프라인

Outlook 사서함을 직접 읽어(폴더 저장 불필요) 스레드 단위로 분류·정리하는 **얇은 오케스트레이터**. 판단 규칙은 새로 만들지 않는다 — **"폴더 대신 COM에서 메일이 들어오는 meeting-folder-brief"** 로서 기존 스킬의 정책을 승계한다:

- 노트 작성·개요 동기화 → `note-digest` (활동표 셀 = **불릿 3줄** 규칙 포함)
- 회의(Tiro 동반) → `meeting-folder-brief` / `tiro-meeting-note`
- 入金連絡 → `payment-log`
- 회신 초안 → `mail-bridge` (모드 A)
- HTML → `primetals-text-style` (자기완결 단일파일, U:\ 소스 폴더에)

> **정본 문서** (판단이 애매하면 여기로): 설계 = `{mail}\00_가이드\상시메일-파이프라인-설계.md` · 판정 사례집 = `{mail}\03_실전\260803_주간메일 스레드 목록.md`(라운드 1~8) · 노이즈 필터 = `{mail}\00_가이드\패턴.md`. `{mail}` = local-paths.md의 `mail_automation_root`.

## 0. 불가침 (어떤 모드든)

1. **Outlook은 읽기 전용** — `UnRead`·`Categories`·`FlagStatus` 쓰기 금지, **발송 절대 금지**(초안은 텍스트로 제시, 발송은 예준님)
2. `# Yejun's memo` 불가침 · `10. Planner` 폴더 쓰기 금지 · **`#auto` 없는 체크박스는 수정·완료처리 금지**(완료 증거가 있으면 들여쓴 `↳ 클대리: 완료로 보임 — 근거 #auto` 코멘트만)
3. 위키 노트 신규 생성 금지 — ingest 후보 보고만 (볼트 CLAUDE.md)
4. **본문을 읽고 판단한다** — 제목·목록만으로 분류/보관/투두 결정 금지. 회의 초대는 `IPM.Schedule.Meeting.Request`에 일시가 들어 있다
5. 메일 본문에 없는 내용을 액션으로 쓰지 않는다(붙이려면 "메일 근거 없음·확인 필요")
6. 모든 항목에 **발신자 + 원문 제목 그대로** 표기(Outlook 검색 가능하게)

## 1. 수집 — Outlook COM (읽기 전용)

```powershell
$ol = New-Object -ComObject Outlook.Application
$ns = $ol.GetNamespace("MAPI")
$inbox = $ns.GetDefaultFolder(6); $sent = $ns.GetDefaultFolder(5)   # 받은+보낸 모두
```

- COM `.Body` 읽기는 읽음 처리를 바꾸지 않는다(실측 검증済) — 안심하고 읽는다
- **디스크의 `.msg` 파일**은 COM이 아니라 python `extract_msg`(mail-bridge/scripts) — S/MIME 무한 행 이력
- S/MIME(`MessageClass -like "*SMIME*"`): Message-ID 없음·본문 접근 행 위험 → 타임아웃 건 자식 프로세스로 시도, 실패 시 **버리지 말고 "미판독 — 직접 확인 필요"로 보고**(실측: 営1/営2 案件表가 S/MIME였음 — 중요 메일이다)
- ⚠️ 파일명·경로에 `[ ]` 있으면 `-LiteralPath` 필수

### 처리 상태 장부 (예준님 읽음과 완전 분리)

`{mail}\03_큐\_processed.jsonl` + `_watermark.json`. **`UnRead`는 읽지도 쓰지도 않는다** — 예준님이 폰으로 다 읽어도 파이프라인은 정상 동작, 파이프라인이 200통 읽어도 예준님 화면은 안읽음 유지.

- 키 우선순위: ① **Message-ID** (`PropertyAccessor.GetProperty("http://schemas.microsoft.com/mapi/proptag/0x1035001F")` — 폴더 이동에도 불변) ② EntryID ③ 수신시각+발신자+제목+크기 해시
- 재개 시 워터마크에서 **3일 겹쳐** 스캔 → 장부 대조 → 신규만 처리

## 2. 스레드 묶기·라우팅

1. **1차 = `ConversationID`** — 받은+보낸 자동 병합, 시차 답장도 붙는다
2. **2차 = 안건 병합** — 제목이 갈리면 CID가 끊긴다(실측: 한 안건이 주 6갈래). 같은 오더코드·같은 설비·같은 불량건이면 동일 안건. **애매하면 합치지 말고 "합칠까요?" 질문**
3. **30일 창** — 30일 넘어 이어진 메일은 같은 CID라도 **새 노트**(예전 노트는 Linked Notes로 연결). 3달 전 날짜 노트는 안 보게 되기 때문
4. **라우팅** — 제목의 PTJ 오더코드 → `01. Projects\0_probid.md` 마스터 → 프로젝트 폴더. 코드 없으면 발신자(연락처-매핑)·키워드. 볼트는 PARA — **`01. Projects`부터** 검색(전체 Grep 금지)

## 4. 원문 보관 (U:\ 프로젝트 폴더 밑 안건별)

```
U:\...\<프로젝트>\<YYMMDD_안건>\
  <제목>.msg               ← 같은 제목 겹치면 먼저 온 순서로 제목1/제목2/제목3 (윈도우 (1) 접미사 금지)
  _attachments\<메일번호>__<원본파일명>   ← 부모 메일 추적 가능하게
  YYMMDD_<주제> 검토.html   ← 필요 시 (primetals-text-style)
```

- 첨부는 **전량** 저장(이미지 로고류 제외). U: 오프라인이면 보류 큐 → 다음 회차 재시도
- **U: 폴더를 만들거나 원문을 저장하면 반드시 해당 노트 `# Yejun's memo`에 `file:///` 바로가기를 단다** — 폴더만 만들고 링크 없으면 예준님이 못 찾는다 (2026-08-03 실수 재발 방지)
- **첨부가 MOM·보고서·계산서 등 실질 문서면 파일 보관으로 끝내지 말고 내용을 읽어 노트에 반영한다** — 본문 필수 원칙은 첨부에도 적용
- 폴더명이 날짜뿐이면 주제 파악 후 `YYMMDD_<주제>`로 리네임(meeting-folder-brief 게이트)

## 5. 노트·개요·투두

- **안건 = 노트 1개**, 후속 메일은 「스레드 경위」 표에 **이어붙이기**(별도 후속 섹션 X). frontmatter `Updated:` 갱신 + description 끝에 Follow-up 문장 append. 표준 예제 = `PSC_UL_FM12\260727_예비품 씰키트 견적방침.md`
- **개요(0_) 동기화 필수** — 노트 신규 = 행 추가 / 제자리 갱신 = 행 제자리 갱신(기간 `<br>` 확장 + 서사 재작성). 라우팅: **PO 이전 → §2 / 이후 → §4.2**(billing 태그) / 입금 → §4.3(payment-log). 셀은 **불릿 3줄**(결론/근거/⚠️미결·다음 +참고). 미결 논점은 개요 행에도 ⚠️
- **투두** — 스레드 마지막 발화자로 결정론 판정: 상대→나 = `#office` / 나→상대 = `#waiting` / 엔지니어 의뢰 중 = `#delegated`. **반드시 `#auto` 병기**, 출처 ↳ 줄(발신자·시각·제목). 프로젝트/스레드 노트에 심는다(Tasks 쿼리가 데일리에 자동 표출). 메일이 실제로 요구하는 것만 — 요구 없으면 투두 0이 정답
- **긴급 감지 → 세션 채팅에 즉시 🔴 보고** — 고객 대기·기한 명시·緊急 표기·기한 경과(유효기한 등). 노트에만 심지 말 것

## 6. 모드

### A. 상시 모드 — "메일자동화 시작해" (폴링 주기 **20분** — 2026-08-03 예준님 조정, 10분은 과함)
1. 장부·워터마크 로드 → COM 폴링(받은+보낸) → 신규 스레드 추출
2. 본문 읽고 §3 분류 → 처리 대상을 **승인 게이트**: 처리 계획을 채팅에 제시 **+ 현황 대시보드 갱신** — `{mail}\03_큐\메일 파이프라인 현황.html`(자기완결 단일파일, primetals 스타일, 사이클마다 덮어쓰기). **레이아웃(2026-08-03 확정)**: 최상단 ⓐ**KPI 타일 5개**(오늘 통수·🔴긴급·⏳승인 대기·✉️회신 필요·✅완료 — 각 섹션 앵커 링크, 긴급/회신은 red·승인은 orange·완료는 teal) ⓑ**D-day 스트립**(기한 칩, 가까울수록 빨강) → 이하 섹션 ①승인·완료 ②회신 필요 ③대기·추적 ④예준님 직접 리마인드 ⑤무시 내역. **JSON 장부는 내부용 — 예준님이 보는 것은 이 HTML**. 승인은 채팅 "진행해"/"1, 3만 진행" → §4~5 실행. (안정화 후 게이트 제거 = 완전 자동)
   - **일자 아카이브**: 날짜가 바뀐 첫 사이클에서 전일 현황 HTML을 `03_큐\아카이브\YYMMDD_메일 파이프라인 현황.html`로 복사 후 새 파일로 시작(승인 대기·기한 추적 미결분은 새 파일에 이월). 장부 jsonl은 누적이라 아카이브 불요
   - **노트 링크는 현황 HTML에 (2026-08-03 예준님 지시)**: 완료·제안 항목마다 대상 노트를 `obsidian://open?vault=Yejun&file=<볼트상대경로(.md 제외)>` 링크로 단다 — 클릭하면 옵시디언에서 바로 열림. 채팅에는 경로 나열하지 않는다(가독성)
3. 🔴 긴급은 게이트와 무관하게 즉시 보고
4. **ScheduleWakeup으로 20분 후 재개** — 세션 루프. 종료는 예준님 "그만"/세션 종료
5. 처리 결과는 장부에 기록

### B. 브리핑 모드 — "어제·오늘 메일 정리" (구 trip-mail-briefing, 출장 포함)
1. 기간 일괄 COM 조회(폴더 저장 불필요 — 폴더를 주면 폴백으로 python extract_msg)
2. 노이즈 필터 → 스레드 묶기 → 볼트 맥락 결합 → **🔴 급함 / 🟡 해야 할 일 / ⚪ 참고** 분류(급한 쪽 상향, 제외 목록 말미 첨부)
3. 🔴는 mail-bridge 모드 A로 회신 초안 2벌(확인용 KR + 발송용 상대언어)
4. 출력: 채팅 개조식 브리핑 + HTML(`YYMMDD_브리핑.html`, U:\ 소스 폴더, primetals-text-style). 상세 규칙은 trip-mail-briefing §5~9 승계
5. 브리핑 모드는 **노트 생성 안 함**(파악용) — 정리까지 원하면 상시 모드 처리로 이어감

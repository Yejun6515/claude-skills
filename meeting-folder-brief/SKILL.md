# meeting-folder-brief — 폴더명 하나로 검토 HTML + 옵시디언 노트 + Tiro

회의·안건의 **소스 폴더**(보통 `U:\新_海外営業部\Kim Yejun\...` 아래 메일·엑셀·문서 묶음) 하나를 받아, 매번 반복하던 작업(위키 확인 → 소스 읽기 → Tiro 매칭 → 회의록 노트 → HTML 검토자료)을 **정해진 순서로 한 번에** 수행한다.

> **이 스킬은 얇은 오케스트레이터다.** 각 단계의 상세 규칙은 기존 스킬에 있고, 여기서는 **호출 순서 + HTML 검토자료 생성 단계 + 저장/명명 규칙**만 정의한다. 각 단계는 해당 스킬의 정책을 그대로 따른다:
> - 위키 확인 → `steel-project-wiki-context`
> - 소스 추출·노트 작성·프로젝트 폴더 삽입·위키 연결 → `note-digest`
> - Tiro 요약 가져오기 → `tiro-meeting-note`
> - HTML/문서 브랜드 스타일 → `primetals-text-style`
> - 入金連絡(입금연락) 메일 → `payment-log`

> **예외 위임**: 폴더에 `入金連絡`·`입금` .msg가 들어 있으면 그 메일은 **`payment-log`로 넘긴다**(첨부 이미지 표 판독 + 개요 §4.3 갱신이 필요해 일반 note-digest 경로로는 처리되지 않음). 폴더에 그 메일만 있으면 이 스킬을 돌리지 않고 payment-log만 실행한다.

## 언제 사용하나
- 사용자가 **소스 폴더 경로/이름 하나**를 주고 "검토해서 HTML + 옵시디언 노트 + Tiro 확인해줘", "이 폴더 정리해줘(끝까지)", "[폴더명] 해줘" 류로 요청할 때.
- 한 회의/안건의 산출물(메일 의사록 + 첨부 엑셀·문서 + Tiro 녹음)을 **노트 1개 + HTML 검토자료 1개**로 묶고 싶을 때.
- 단순히 노트만(HTML 없이) 원하면 `note-digest`, Tiro 요약만 옮기려면 `tiro-meeting-note`로 충분 — 이 스킬은 **둘 다 + 위키 확인 + HTML**까지 한 번에 할 때.

## 프로젝트 폴더 경로 (공통 정본)

**새 노트·새 폴더를 만들거나 프로젝트 자료를 찾을 때, 탐색하지 말고 매핑표에서 볼트 경로와 U: 경로를 동시에 얻는다.**

- 정본: `C:\Users\Z006K14G\Desktop\Yejun\01. Projects\0_노트정리 진행상황.md` 의 「📁 프로젝트 폴더 매핑」 절 (포인터: `.claude\skills\_config\project-folder-map.md`)
- 볼트 전체 Grep·U: 전체 탐색 금지. 표에 **없는 프로젝트는 지어내지 말고 예준님께 확인**하고, 확인되면 그 표에 한 줄 추가한다
- 폴더 규칙도 같은 절에 있다 — 3계층(회사→프로젝트→케이스) · 케이스 `YYMMDD_주제` · `_attachments\<메일번호>__<파일명>` · 제출물 `submission\` · HTML은 U:에 두고 노트엔 `file:///` 링크
- 노트를 만들면 `# Yejun's memo`에 **소스 폴더 `file:///` 바로가기 필수** — 표가 이 링크에서 재도출되므로 빠뜨리면 표가 늙는다
## 입력
- 소스 폴더 경로(예: `U:\新_海外営業部\Kim Yejun\1_POSCO\7_POSCO_P2H_Production\260629_견적설명회`) 또는 그 폴더명만. 폴더명만 주면 부모 경로를 맥락(직전 대화·프로젝트)으로 추정하고, 모호하면 전체 경로를 되묻는다.

### 알려진 상시 폴더
- `U:\新_海外営業部\Kim Yejun\50_Monthly meeting` = **월례회의(Monthly meeting) 폴더**. 여기 자료로 노트 정리를 요청받으면 반드시 §2(폴더 자료 읽기)를 먼저 수행하고, 그 자료의 용어를 기준으로 Tiro 전사를 대조·해석한다(§3의 "폴더 자료 = 용어 기준 사전" 규칙). 월례회의는 참석 프로젝트가 여럿 섞이므로 오인식 위험이 특히 높다.

## 워크플로우 (이 순서를 지킨다)

### 1. 위키 컨텍스트 확인
- 폴더 내용/경로에서 **고객사·라인코드·설비**(POSCO·P2H·K3CX 등)를 잡고, `steel-project-wiki-context` 절차로 **위키(`90. Wiki`) + 프로젝트 폴더의 현황·마스터 스케줄·최근 노트 1~3개**를 먼저 읽는다. 철강 안건이면 필수, 무관하면 건너뛴다.
- 목적: 이 회의가 **직전 진행상황의 어디에 위치하는지** 파악해, 노트·HTML에 "직전 대비 변화"를 정확히 쓰기 위함.

### 2. 폴더 안 소스 읽기
- `note-digest`의 추출 스크립트로 폴더 전체를 덤프:
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.claude\skills\note-digest\scripts\extract_sources.ps1" -FolderPath "<소스 폴더>"
  ```
  → 생성된 `_extracted_sources.txt`를 **Read**. PDF·본문 박힌 사진은 `note-digest` 규칙대로 **Read 도구로 직접** 본다.
- ⚠️ **엑셀은 시트당 80행에서 잘린다**(`-MaxRows` 기본값). 시트 헤더의 `rows=NNN`이 80보다 크면 표가 중간에 끊긴 것이므로 `-MaxRows <NNN>`으로 다시 돌린다. 월례회의 案件表처럼 400행대 표가 흔하다.
- 메일(무슨 일) ↔ 첨부 엑셀·도면·사양(근거·수치)을 **하나의 사건으로 교차**해 파악한다(note-digest 핵심2).
- 🔴 **[필수 게이트] 날짜만 있는 폴더는 내용 파악 후 이름을 바꾼다** (2026-07-20 예준님 지시, 2026-07-27 재확인 — 실제로 한 번 누락됨): 폴더명이 `YYMMDD`뿐이면(주제 없음), 소스를 읽어 주제를 파악한 뒤 형제 폴더 컨벤션에 맞춰 `YYMMDD_<주제>`로 **Rename-Item**한다(예: `260720` → `260720_아이로닝롤 녹 원인분석·SEJAL 조사의뢰`, `260706` → `260706_HSC 회답·견적착수지시`). **HTML 생성·노트 링크 작성 전에** 리네임해야 `file:///` 링크가 새 경로를 가리킨다. 바꾼 이름은 §6 보고에 포함.
  - ⚠️ **판단 기준은 디스크의 실제 폴더명**이다. 사용자가 준 경로에 메모성 접미사가 붙어 있어도(예: "260706 Tiro없음"이라 줬는데 실제 폴더는 `260706`), 실제 폴더명이 날짜뿐이면 이 게이트가 발동한다. §5 HTML 저장 직전에 "리네임 필요 여부"를 한 번 더 자문하고, 날짜만인 채로 HTML을 쓰지 않는다.
- 읽으면서 **기준 용어집을 뽑아 둔다** — 소스 자료에 나오는 설비명·기술용어·라인코드·프로젝트명·인명·수치 표기. 이것이 §3에서 Tiro 전사 오인식을 잡는 **기준 사전**이 된다.

### 3. Tiro 매칭
- Tiro MCP로 같은 회의 녹음을 찾는다: `mcp__tiro__list_notes`(keyword=라인코드/프로젝트, 또는 날짜로 필터) → 폴더 날짜와 같은 **녹음 1건**을 고른다(제목 표기가 폴더명과 달라도 날짜·주제로 매칭. 예: 폴더 "견적설명회" ↔ 메일 "見積方針会議" ↔ Tiro "견적서검토회"가 동일 회의일 수 있음).
- `mcp__tiro__get_note`(include=`["summary","documents"]`)로 내용을 가져와 노트 **`# 클대리 정리` 안 `## 회의 내용 (Tiro 녹음 기반)`** 소제목 아래에 1회 기입한다. **`# 티대리 정리` 섹션은 만들지 않는다**(2026-07-29 티대리 생략 규칙 — 내용이 클대리 정리에 들어가므로 중복. 원문 추적은 frontmatter `Tiro Address` + `# Yejun's memo`의 Tiro 바로가기 링크로. 기존 노트에 예준님이 채워 둔 `# 티대리 정리`가 있으면 그대로 둔다). **어느 쪽인지에 따라 처리가 다르다(`tiro-meeting-note` §1~§1.5와 동일):**
  - **Tiro가 만든 "옵시디언 회의록" 문서가 있으면** → 그대로 옮긴다. **재요약·문장 변경·구어→문어 변환 금지.**
  - **문서 없이 요약만 있으면 → 직접 정리 모드** — summary(부족하면 `get_note_transcript`로 보충)를 `tiro-meeting-note` **§1.5 [옵시디언 회의록 양식]**으로 재구성해 넣는다: `## 1. Background`(Meeting Purpose) / `## 2. Meeting Minutes`(합의 사항 → 기술 이슈 ⚠️ → Q&A 순) / `## 3. Follow ups`(PTJ 과제·협력사 과제·고객사 과제). 한글 개조식(~함), 이모지 ✅🟡🔴⚠️⭕, 우선순위는 높음/중간/낮음, 마감 `YYYY.MM.DD`·담당 1명, 빈 섹션 삭제, 과도한 설명은 "첨부파일 참조", 추측 금지.
  - 어느 경우든 아래 "용어 치환" 규칙에 따라 확정된 오인식 고유명사는 치환한다.
- **폴더 자료 = 용어 기준 사전.** Tiro 요약/전사를 읽을 때는 §2에서 뽑아 둔 폴더 소스의 용어집을 옆에 두고 대조한다 — Tiro 표기와 소스 문서 표기가 다르면 **소스 문서 쪽이 정(正)**이다(예: Limiter=VinMetal, 헤저=Edger, 초우수=長油柱, 휴대화=径大化, 연타=벤더).
- **Tiro 요약 용어 치환 (2026-07-06 예준님 결정, 방식 B).** 소스 자료(폴더 문서·위키·볼트)로 **확정된 고유명사 오인식만** 요약 본문에서 정식 표기로 치환한다. 치환하면 frontmatter `Tiro Edited: corrected`(치환 없으면 `raw`), **치환 내역은 `# 클대리 정리`의 용어 보정표**에 남긴다(원문 표기는 보정표 + frontmatter의 Tiro 웹 원본으로 보존). **불확실·소스에 없는 표기는 치환하지 않고** 보정표에 "추정/미확인"으로만 기록. 문장 구조·내용에는 손대지 않는다.
- **오인식 사전 축적**: 새로 확정된 오인식 패턴·신규 고유명사는 `{vault}\100. Market information\Tiro 등록 단어.md`(등록 단어 리스트 + 오인식 패턴 표)에 추가하고 최종 업데이트 날짜를 갱신한다 — 예준님이 Tiro 앱 등록단어에 반영하는 원본.
- 녹음이 없으면 그 사실을 알리고 Tiro 단계는 생략(노트는 메일·문서 기반 Event/회의록으로).

### 4. Obsidian 노트 작성
- `note-digest` §3~4.5를 그대로 따른다:
  - **템플릿** : Tiro 녹음이 있으면 `회의록_Template`, 없으면 `Event template`. 작업 전 `50. Template\`에서 정본 Read. **본문은 `# Yejun's memo` / `# 클대리 정리` 2개만 쓰고 `# 티대리 정리`는 만들지 않는다**(§3).
  - **섹션 규칙** : 소스 폴더 바로가기 + Tiro 노트 바로가기 = `# Yejun's memo`, 내 분석 + Tiro 요약(`## 회의 내용 (Tiro 녹음 기반)`) 전부 = `# 클대리 정리`. HTML 링크는 `# 클대리 정리`의 `## 정리 자료 (HTML)`에 `file:///`로.
  - **저장 폴더는 AskUserQuestion으로 확인**(§4) — 소스가 프로젝트 소스 트리 안이라 대상이 명확해도 확인. 파일명 `YYMMDD_<주제>.md`.
  - **mentions** : Contacts 대조 후 **확인받아야** 기입(§3.5). 내부 회의 등 참석자가 많으면 비워 두고 보고에 사유를 남겨도 된다.
  - **위키 연결**(§4.5) : `0_Wiki MOC.md` 어휘로 `# 클대리 정리` 안 `## 관련 위키`에 `[[링크]]`, 없는 개념은 **ingest 후보**로 보고(생성 금지).

### 4.6 같은 안건이면 통합한다 (2026-07-29 예준님 지시)
메일은 **같은 스레드가 며칠에 걸쳐 왔다갔다** 한다. 날짜가 다르다고 별건으로 쌓지 말고, **같은 안건이면 하나로 묶어서** 다룬다.

**(a) 폴더에 메일이 추가된 경우 = 갱신, 새 노트 아님**
- 이미 처리한 폴더에 예준님이 메일을 더 넣었거나 `.msg`가 갱신(파일 크기·타임스탬프 변화)되면 → `extract_sources.ps1`을 **다시 돌려** 스레드 전체를 읽고, **기존 노트·기존 HTML을 제자리 갱신**한다. 같은 스레드로 노트를 새로 만들지 않는다.
- 갱신 시 손볼 곳: 경위 표(신규 통 추가) · 개요·변화점·리스크(새 사실 반영) · 다음 액션(**해결된 항목은 `[x]`로 닫고 신규 액션 추가**) · frontmatter `description`(영문, 최신 상태로 다시 씀) · 출처(대표 메일을 **최신 통**으로, 「스레드 N통」 표기 갱신) · HTML 헤더에 「YYYY-MM-DD 갱신」 표기.
- 노트 파일명·폴더명은 **그대로 둔다**(링크 안정성). 주제 자체가 바뀌었을 때만 리네임하고 §6에 보고.
- 스레드가 확장되며 **새 논점이 붙으면**(예: 납기 회신 + 별건 SV 시기 조회) 기존 섹션에 욱여넣지 말고 **별도 섹션**으로 세우되, 노트·HTML은 여전히 1개로 유지한다.

**(b) 개요 노트 §4.2 Project management Event = 안건 1행**
- 같은 안건의 후속·회신은 **행을 새로 만들지 않고 기존 행에 합친다**:
  - 일자 칸 = **범위 표기** — `2026-07-27<br>~07-29` (마크다운 표 안이므로 줄바꿈은 `<br>`)
  - 안건 칸 = 안건 전체를 아우르는 이름 (예: 「Mill Drive 중간축 250mm 부족」 + 「대품 납기·통관정보 요청」 → **「Mill Drive 중간축 250mm 부족·대품 수배」**)
  - 핵심 내용 칸 = **불릿 3줄 형식으로 재작성**(2026-08-03 확정): `• **결론**: …<br>• **근거**: …<br>• ⚠️ **미결·다음**: …` (+필요 시 `• **참고**:`). 두 요약을 합칠 때는 발견→원인확정→대응·납기→미결 흐름을 결론/근거/미결 불릿에 배분. 단순 이어붙이기 금지, 중복 문구 제거.
  - 관련 노트 칸 = 관련 노트를 `·`로 **모두 나열**(노트 자체는 날짜별로 유지)
- **동일 안건 판정** : 같은 메일 스레드(제목 RE: 연쇄)이거나, 같은 설비·부품·불량건의 연속 대응이면 동일 안건으로 본다. 판단이 애매하면 합치지 말고 §6 보고에서 "합칠까요?"로 묻는다.
- 정렬은 **최신순 유지** — 통합 행은 범위의 **가장 이른 날짜**가 아니라 표의 기존 위치(최신 날짜 기준)에 둔다.

### 5. HTML 검토자료 생성 (이 스킬의 추가 단계)
- `primetals-text-style`를 적용한 **자기완결 단일파일 HTML**을 만든다(브랜드 팔레트 + 한국어 기본, `reference/examples/krakatau_survey_KO.html` 구조 미러: 네이비 헤더+오렌지 룰, 오렌지 섹션 배지, 검정 본문, 티얼 링크, 상태 태그). 이미지가 있으면 base64 인라인 임베드([[html-self-contained-default]]).
- **내용** = 노트 `# 클대리 정리` 분석을 HTML로 재구성(개요·범위·일정·전략·핵심표·미결·출처). 메일+엑셀+Tiro를 **통합한 검토본**이지 단순 나열이 아니다.
- **저장 위치 = 소스 폴더(U:\ ...)** — 볼트 용량 절약을 위해 볼트에 두지 않는다([[html-output-in-source-folder]]). 파일명 `YYMMDD_<프로젝트> <주제> 검토.html`. **저장 직전 체크: 소스 폴더명이 아직 날짜뿐이면 §2 리네임 게이트로 돌아가 먼저 리네임**(리네임 후 경로로 저장·링크).
- 노트 `## 정리 자료 (HTML)`에 이 파일을 `file:///`(소스 폴더 경로)로 링크.

### 5.5 일본어 단어 피커 (자동 — tiro-word-tts 1단계)
- §3에서 매칭된 Tiro 녹음이 **일본어 회의**면, `tiro-word-tts` 스킬 1단계를 실행한다:
  `get_note_transcript` → 단어 추출(`_tiro_words.json`) → `build_picker.py` → **`단어피커_{제목}.html`을 소스 폴더에** 생성(검토 HTML과 나란히).
- 이후 사용자가 피커에서 고른 목록을 붙여넣으면 tiro-word-tts 2단계(볼트 단어 노트 → TTS → Drive 12_TTS 업로드)로 이어진다. 한국어 회의·녹음 없음이면 건너뛴다.

### 6. 보고
- 만든 것: **노트 경로 + HTML 경로 + Tiro 매칭 결과 + (일본어 회의면) 단어 피커 경로** 한눈에. **갱신 모드였으면**(§4.6a) 새로 만든 게 아니라 **무엇을 어떻게 갱신했는지**(추가된 메일 통수·바뀐 결론·닫힌 액션)와 **§4.2에서 어느 행과 통합했는지**를 밝힌다. **폴더 리네임 여부**(했으면 새 이름, 날짜만 폴더인데 안 했으면 사유)도 반드시 포함.
- **확인/미결**: 노트 저장 폴더(확인됨), mentions 처리, **추가한 위키 링크 / 신규 ingest 후보**, 그리고 소스에서 확인 필요한 항목(예: 약어·제작처 명칭).

## 규칙 (각 스킬 정책 승계 + 이 스킬 고정값)
- **순서 고정** : 1(위키)→2(소스)→3(Tiro)→4(노트)→5(HTML)→6(보고). 위키 확인 없이 노트/HTML로 직행하지 않는다(틀린 맥락 방지).
- **확인 게이트** : 노트 저장 폴더(AskUserQuestion), mentions는 **사용자 확인 후에만**. 폴더가 명확해도 확인.
- **HTML은 소스 폴더(U:\)에**, 노트는 **볼트 프로젝트 폴더**에. 둘을 바꾸지 않는다.
- **# Yejun's memo 불가침**; **`# 티대리 정리`는 새로 만들지 않는다**(Tiro 내용은 `# 클대리 정리`로, §3). 기존 노트에 있는 `# 티대리 정리`는 §3의 확정 고유명사 치환만 허용(그 외 불변, `Tiro Edited`로 상태 표시). 위키 노트는 읽기 전용(생성은 `wiki-ingest`).
- **같은 안건은 하나로** — 폴더에 메일이 추가되면 새 노트가 아니라 **기존 노트·HTML 갱신**, 개요 §4.2는 **일자 범위 + 통합 요약 1행**(§4.6).
- **개조식(~함)** 한국어, BOM 없는 UTF-8, 날짜 `YYYY-MM-DD`.
- 소스에 **없는 사실은 지어내지 않는다**(불명확은 "미확인"으로 표기하고 보고).

# mail-bridge — PTJ 영업 메일 브릿지

예준님(PTJ 영업)이 하는 **고객↔일본 엔지니어 메일 중계**를 대신한다. 단순 번역이 아니라, 옵시디언 볼트를 읽어 **라우팅(누구에게/CC/어느 스레드)을 판단**하고 영업 맥락을 얹어 전달 초안을 만드는 브릿지.

## 핵심 원칙 (사용자 확정)
- **초안은 내용 위주.** 메일 발송은 예준님이 직접 하므로, 헤더 완비된 완성 메일이 아니라 **바로 쓸 내용**을 준다.
- **항상 두 벌, 한국어를 먼저:** ① 예준님 확인용 **한국어** → ② 실제 발송용 **상대 언어**(JP 등). 순서 고정.
- **호칭:** PTJ 사내 = `さん`("상") / 타사(日立·WNC·고객) = `様`("님"). 한국어 확인용에도 동일 구분 적용.
- **인사말:** 사내·상시 파트너(日立)에는 「お世話になっております」 **생략**, 첫 줄부터 본론. 고객·대리점에는 사용.
- **PTKR(음대일 등)은 CC 원칙 제외.**
- 없는 사실은 지어내지 않는다. 불명확은 "미확인"으로 표시하고 surface한다(판단은 예준님).
- **요청받지 않은 우려·타 안건을 초안에 끌어오지 않는다**(안건 오염, 케이스 #16). 원문 표·수치는 요약하지 말고 **그대로** 옮긴다.

## 지식 소스 (매번 실행 시 읽는다)
규칙과 사전은 스킬에 하드코딩하지 않는다. 아래 파일을 **읽어서** 최신 규칙으로 동작한다 (예준님이 계속 업데이트함).
경로는 PC마다 다르다 — `%USERPROFILE%\.claude\skills\_config\local-paths.md`에서 `{vault}`=`vault_root:`, `{mail}`=`mail_automation_root:` 값을 읽는다(없으면 사용자에게 물어 저장 — `_config\README.md`):
- `{mail}\00_가이드\패턴.md` — 라우팅·작문 규칙, 출력 형식, 사용자 선호
- `{mail}\02_매핑\연락처-매핑.md` — 고객/엔지니어 이메일, To/CC 기본 규칙, 용어 매핑
- 옵시디언 볼트: `{vault}` (프로젝트 MOC·Event 노트·`90. Wiki`·`20. Contacts`)

## 모드 A — 전달 초안 만들기 (주 용도)

입력: 받은 메일 1통 (`.msg` 파일 / 폴더 / 붙여넣은 본문).

1. **읽기.** `.msg`면 `scripts\extract_msg.ps1`로 덤프 → Read.
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File "<skillDir>\scripts\extract_msg.ps1" -FolderPath "<폴더>"
   ```
   제목/발신/수신/CC/본문/첨부를 파악. 답장 체인(RE:)은 과거 메일이 통째로 들어있으니 스레드 흐름을 시간순으로 푼다.
2. **패턴·매핑 로드.** 위 지식 소스 두 파일을 읽는다.
3. **라우팅.** 메일에서 프로젝트/설비/코드 키워드를 뽑아:
   - 먼저 `02_매핑\연락처-매핑.md`에서 프로젝트·담당자·CC 규칙 확인.
   - 볼트에서 관련 **프로젝트 MOC**(예: `PTJ Menu Order Code`)와 최근 Event 노트를 Grep/Read → **프로젝트 코드로 기존 상대측 스레드를 찾아 그 스레드에 RE로 회신**하는 게 기본.
   - **To** = 해당 안건 담당 엔지니어 / **CC** = 그 프로젝트 스레드·최근 방문 참가자 전원 / **PTKR 제외**.
   - 근거를 함께 제시(어느 노트/스레드에서 왔는지).
4. **초안 작성.** `패턴.md`의 작문 구조를 따른다. KR2JP 기본형:
   ```
   ① 커버노트 — 요청 핵심 1~2줄 + 영업 맥락(견적 일정·직전 미팅 등, 원문에 없어도 능동 추가)
   ② =<안건약칭> QTE= — 원문 전체 번역(충실, bullet 유지, 매핑표 고정 용어)
   ③ =UNQTE=
   ④ 맺음말 + 서명(キム)
   ```
   역방향(JP2KR/JP2CN)은 상대 언어로 쓰되 예준님 확인용 한국어를 반드시 병기.
5. **출력.** 아래 형식으로 채팅에 제시(내용 위주). **한국어가 먼저**:
   - **회신 스레드**: (제목) / **To**: / **CC**: / **제외**: / **라우팅 근거**: 1줄
   - **【예준님 확인용 (한국어)】** — 무엇을 어떻게 전달하는지
   - **【발송용 (일본어 등)】** — 복사용 본문
   - To에 사내+사외가 섞이면 **수신자별 블록**으로 나눠 각자에게 부탁할 것을 명시(케이스 #16).
   - 전달이 2단 이상 거쳤으면 **중첩 QTE 마커**(`=WN QTE=` → `=POSCO QTE=` → `=QTE=`)로 출처 계층을 보존.
6. **자동 유지.** 메일에서 새 이메일/담당자/용어를 발견하면 `02_매핑\연락처-매핑.md`와 볼트 연락처(`20. Contacts`)에 반영(사용자 승인 없이 채워도 OK — 확정 선호).
7. **인물 이력 축적.** 이 메일에 등장한 주요 인물(발신·주요 수신자)의 `20. Contacts` 노트 `## 5. Remarks`에 **날짜 개조식 한 줄**을 이력 **맨 위**에 추가 (아래 "인물 이력 축적" 규칙 참조).

## 모드 B — 케이스 학습 (규칙 성장)

입력: 케이스 폴더 `01_케이스\케이스NN_...\` (하위 `1.`=먼저 받음 / `2.`=뒤에 보냄).

1. 두 폴더의 `.msg`를 각각 추출해 **원문 ↔ 보낸 것**을 확보.
2. **대조 분석**: 라우팅(원문 To/CC vs 보낸 To/CC, 어느 스레드에 붙였나), 요약 밀도, 톤, 커버노트에 덧붙인 영업 맥락, 용어 매핑, 생략/강조.
3. 볼트에서 해당 프로젝트를 찾아 라우팅 근거를 검증.
4. **확인 포인트를 surface**(불명확·판단 필요 항목)하고 예준님 답을 받아,
5. 배운 것을 `00_가이드\패턴.md`(규칙·케이스 로그)와 `02_매핑\연락처-매핑.md`(연락처·CC·용어)에 반영, 볼트 연락처도 자동 채움.
6. 케이스에 등장한 주요 인물의 `20. Contacts` 노트 `## 5. Remarks`에 이력 한 줄 추가 — **맨 위(최신 먼저)** (아래 "인물 이력 축적").

## 인물 이력 축적 (20. Contacts Remarks)
목적: 다음에 그 사람을 만나거나 응대하기 전에 노트 하나로 이력·성향을 파악. **위키(90. Wiki)엔 인물을 두지 않으므로**(볼트 규칙) 사람 정보의 제자리는 연락처 노트다.
- **대상**: 해당 메일/케이스의 발신자와 주요 수신자(고객 담당자·일본 엔지니어). 단순 CC 참조자는 생략 가능.
- **위치**: 각자 `20. Contacts\<회사>\<이름>.md`의 `## 5. Remarks`. 노트가 없으면 템플릿대로 새로 만든다(frontmatter `Company:` = 소속사 — `Category`는 인물 노트에 쓰지 않음, §1~5 골격).
- **형식**: `- YYYY-MM-DD <핵심 키워드 한 줄> [[관련 노트]]`. **한 줄 요약 + 관련 Event/회의 노트로 링크**가 기본 — 상세는 링크된 노트에 있으니 여기선 키워드만.
- **정렬 = 최신이 맨 위(newest first)** — 새 줄은 `_이력 (mail-bridge 자동 축적):_` 라벨 **바로 아래에 삽입**(맨 끝에 append 금지), 아래로 갈수록 과거. 예외 두 가지: ① `- 역할: …` 인물 소개 줄은 항상 이력 맨 위 고정 ② 날짜 없는 줄(`(일자 미상)`·프로젝트 요약 등)은 이력 맨 아래. 날짜가 `YYYY-MM`·`YYYY`처럼 거친 줄은 같은 기간의 정확한 날짜 줄들 **아래**에 둔다. (2026-07-30 전환 — 기존 212개 노트 일괄 재정렬 완료)
- **짧게 요약.** 개조식(명사·~함 종결), **한 건=한 줄**. 문장 나열·풀어쓰기 금지. 같은 날 여러 건은 한 줄로 묶음. → 이력이 수십 줄 쌓여도 훑어보기 부담 없게.
- **관여 많은 인물은 프로젝트 단위로 압축.** 노트가 수십 개면 날짜별 나열 대신 **프로젝트별 한 줄 + 대표(최근) 노트 링크 "외 다수"**로 묶는다. 오래된 것은 분기/연 단위로 더 압축.
- 기존에 예준님이 손으로 넣은 내용(생일·전화 표 등)은 **건드리지 말고** 그 아래에 자동 이력 블록을 추가. 자동 블록은 `_이력 (mail-bridge 자동 축적):_` 라벨로 시작해 수기 내용과 구분.
- **참석자 소스 = Event 노트 frontmatter `mentions:`.** 회의/Event 노트를 처리할 땐 이름 grep보다 `mentions:`의 `[[인물]]` 목록이 정확 — 그 인물들 노트 Remarks에 해당 노트를 `[[링크]]`로 한 줄 추가. (인물 노트 파일이 곧 mentions 링크 대상)
- **사람 중심만.** 그 사람의 역할/발언/요구/성향/만난 기록만. **프로젝트 진행상황은 프로젝트 MOC·Event 노트에 두고 여기선 링크만** (`[[Event 노트]]`), 복사 금지 → 연락처 노트 = 허브. 프로젝트 노트가 아직 없으면 프로젝트명/코드를 텍스트로.
- **불명확·미확인은 지어내지 않는다.** 확실한 사실만 남긴다.
- **description 동기 갱신.** Remarks에 이력을 append한 뒤 frontmatter `description:`이 낡았으면 같이 갱신한다. 포맷 = **Remarks 2줄 요약**(영어, ~250자): 1줄째 정체(팀·직책·나와의 관계 — 창구/엔지니어/PM 등), 2줄째 반복 등장 프로젝트 + 최근 활동(오래된 건 뭉뚱그림). 이력 없는 인물은 Team·Title 기반 1줄만. (2026-07-06 전체 백필 완료 — 이후는 이 규칙으로 유지)
- `# Yejun's memo` 불가침, (노트에 있으면) `# 티대리 정리`는 확정 오인식 치환 외 불변 (연락처 노트엔 해당 없음).

## 볼트 작업 시 주의
- 볼트 노트 수정 규칙은 `{vault}\CLAUDE.md`를 따른다(`# Yejun's memo` 불가침·기존 `# 티대리 정리`는 확정 오인식 치환만·새 노트엔 `# 티대리 정리`를 만들지 않음, 위키 노트는 읽기만, 인물 원자노트 금지). 단 `20. Contacts` 연락처 노트의 이메일/전화 채우기는 허용.
- `.msg` 본문 대량 추출은 **python `scripts\extract_msg_by_id.py`가 기본**(`pip install extract-msg`, 이 PC 설치됨) — `_headers.txt` 인덱스에서 id 지정 추출. ⚠️ Outlook COM(`extract_msg_by_id.ps1`)은 일부 메일(S/MIME 서명 등)에서 **무한 행** 걸림 — 쓰려면 반드시 백그라운드 태스크로 돌리고, 행 걸린 프로세스를 죽일 땐 자기 세션 트리가 아닌지 CommandLine 확인(2026-07-09 터미널 사망 사고). 헤더 인덱스 생성은 `extract_msg_headers.ps1`(COM), 단건 폴더 덤프는 `extract_msg.ps1`.
